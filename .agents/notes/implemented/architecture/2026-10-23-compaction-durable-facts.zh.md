# Agent Note：压缩事实随摘要文本一同保存

Status: implemented

[English](2026-10-23-compaction-durable-facts.md) | 中文

## 问题

长时间会话会忘记关键信息，原因有两处且彼此独立：

- 压缩范围从第一个非系统表面节点开始，因此操作者最初的需求是最先被压成散文的内容。为子代理设置的任务说明也有同样的命运。
- 没有任何机制把浓缩后的知识带出会话。上下文 keeper 按自己的批次节奏提炼事实，但压缩——恰恰是销毁上下文最多的时刻——没有发布任何可检索的内容，于是下一个会话只能从头推导。

显而易见的修法各自违反既有规则。把项目记忆块注入提示词违反注入策略（记忆必须由工具驱动）。给 `compaction/summary` 增加负载字段要付出持久化确认、重新生成目录、SDK 期望输出变更和类型粘贴的代价，而它携带的仍是摘要文本已有的内容。对被遮蔽区间再跑一次提炼会翻倍模型开销，并与 keeper 的事实重复。

## 决定

- **事实就是普通的检查点文本。** 摘要指令新增 `## Durable Facts` 小节（`decision` / `constraint` / `requirement` / `fact` 条目）。语法与解析器位于 `@deepseek-ai/dsh-compaction-basic/durable-facts` 这一无依赖的纯子路径。消费方导入它；压缩包永远不导入消费方。
- **不改会话格式。** 该小节位于既有 `summary` 块的内容中，因此写入版本、持久化目录和 SDK 期望输出都不受影响。
- **策略属于消费方。** 开关、上限、近似重复阈值和工作区限定由保存事实的插件拥有，而不属于摘要器。因此指令是无条件的：它不会被记录，如果指令随配置变化，就会破坏“可由日志加代码重建”。
- **只在成功时写入。** 事实在 `compaction/summary` 时暂存，在匹配的 `compaction/end` 无错误后写入；机械省略与失败的压缩不写入任何内容。
- **可以固定开头的用户消息。** `pinLeadingUserMessages` 把开头连续的 `user/message` 排除在范围之外，并作为前置上下文重放给摘要器，使辅助请求在固定段之前保持字节相同的前缀。`pinScope: child` 让根会话维持原有边界。

## 影响

- 每次压缩多消耗约 150–400 个输出 token；换来的则是未来会话拿到确切的决定、约束与标识符，而不是逐渐走样的散文。
- 事实通过 `memory_search` 检索而非注入，因此注入策略得以维持，运行中的回合也不会多出额外步骤。
- 压缩事实按来源标记，并限定在来源记录的工作区内，因为单一全局记忆库否则会混淆不同项目。
- 固定会改变压缩遮蔽的 seq 集合。保留固定项本就保护被引用的 seq，而被遮蔽区间仍可通过会话日志读取。

## 被否决的方案

- 增加 `compaction/summary` 负载字段：携带的信息并不多于文本，却付出真实的模式变更代价。
- 对被遮蔽区间再跑一次提炼：模型开销翻倍，事实重复。
- 被动注入记忆：违反注入策略，并给每个运行中的回合增加一步。
- 固定全部内容：被固定的节点永不收缩，预算将无法恢复。
