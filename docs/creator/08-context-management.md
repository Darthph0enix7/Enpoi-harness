# 08 — Context management

The layers a long session passes through, in order, with the knobs that control each. Sources are repo-relative: `packages/…` = the harness repo; `profiles/<profile>/packages/…` = the installed fork packages. Design authority for the whole system: `~/dsh-migration/66-compaction-and-recall-design.md`; live evidence: `~/dsh-migration/evidence/context-eval/`.

Model-visible surface order (top to bottom): system prompt + tool list (frozen) → epoch stubs → segment summaries → state checkpoint (keeper brief) → whiteboard → recent tail (never compacted). Checkpoint and whiteboard are replace-in-place context blocks; segments are frozen once committed (`66…:283-300`).

## 1. Tool-result pruner (deterministic, every turn)

- Middle-span pruning only: when a tool result exceeds `thresholdChars`, keep `headChars` + `\n\n[... tool result middle pruned ...]\n\n` + `tailChars` (`packages/compaction/compaction-tool-result-pruner/src/config.ts:7-14`). Defaults: 8192 / 4096 / 1024 chars.
- Knobs: plugin config `thresholdChars`, `headChars`, `tailChars`; live overrides via `enpoi-orchestration.parameters.compaction.pruneThresholdChars|pruneHeadChars|pruneTailChars`, read per prune (`compaction-tool-result-pruner/src/settings.ts:41-57`).
- Guard: `headChars + marker + tailChars ≤ thresholdChars` must hold; at load a violation throws, and a settings combination that would grow the text is ignored whole (`config.ts:55-63,76-89`).
- Failure mode: a pruned middle is gone from the request but stays in the log — recover with `session_event_read` (eval: 371/371 call pairs pruned, 0 orphans, middles retrievable — `evidence/context-eval/report` figures in `66…:728-731`).

## 2. Context Keeper + Living Brief (background, model-backed)

- The keeper is a SERVICE, not a watcher (`profile/web/packages/enpoi-context-keeper/src/index.ts`). Consumers (Oracle, councils) ask for a fresh brief at their own start. Disable switch: `capabilities.tools.keeper` (default true) — disabled ⇒ no prose distillation, claims extraction, or checkpoint refresh, and consumers degrade to the deterministic fold.
- The prose brief is five sections with a zero-filler rule: 🎯 goal/trajectory, 📚 documentation inventory, 🏛️ invariants/decisions, 🚫 rejected approaches, ⚡ blockers/open questions. Secrets are excluded by prompt instruction, and the memory intake guard drops a credential-shaped keeper claim without failing the claims pass (the producer sees no exception). The brief is consumer/display output and is **not injected** into model requests; the state checkpoint surface message is the model-visible derived state.
- Config defaults (per-wake, live-editable; `parameters.keeper` overrides with clamps): `provider`/`model` = `kilo`/`poolside/laguna-s-2.1:free`; no fallback unless the operator sets both `fallbackProvider` and `fallbackModel`; `leaseMs` 45 s; `maxInputEvents` 80; `maxOutputTokens` 2048 (clamped to the 4096 ceiling); `structuralDistanceK` 24; `minRefreshMs` 60 s; `negativeCacheMs` 120 s; `claimsBatchSize` 8 or `claimsBatchMinutes` 5; `checkpointStaleEvents` 12; `checkpointStaleHours` 24; `checkpointMaxChars` 2400 (validated integer 256–12000).
- Route precedence: `personas.keeper` (with optional `chain` → frozen link list) > plugin Config primary → the keyless kilo seed. A configured fallback link exists only when both fields are set. A route link that fails repeatedly is quarantined in-process; request-shaped failures (`CONTEXT_WINDOW_EXCEEDED`, `INVALID_REQUEST`, `UNSUPPORTED_CONTENT`, `IMAGE_OFFLOAD_REQUIRED`, `FREE_TIER_GATED`) never strike a route.
- Brief freshness order: negative-cache → anti-thrash floor (`minRefreshMs`) → structural distance (`structuralDistanceK`, counted over user/turn/tool events only) → single-flight join → distill. Silence never invalidates prose; a joiner never inherits the originator's abort. A structurally stale `turn/end` schedules one debounced prefetch, and disposal clears the cache/ownership epoch so an in-flight pass cannot publish stale prose.
- Shape gate: a published brief needs ≥1 recognized section header, ≥1 bullet, and ≥40 chars; tool-call echoes, JSON envelopes, markup blobs, and header-less landings are rejected and the route ladder advances.
- Source authority is read from the current model-visible surface, never abandoned raw-log turns. Only an explicit human participant in a root session is `OPERATOR`. A bare `user` producer is visible as `USER_ROLE_UNVERIFIED`; peer/subagent-parent messages are derived; assistant public text excludes private reasoning; tool calls/results are observed, not verified execution.
- **State checkpoint:** append-only `state/checkpoint` event plus one plugin-sourced surface `user/message` that replaces the previous checkpoint node in place. The model path asks for one JSON current-continuity item draft (operator goals/constraints/decisions, observed evidence, unresolved work). Code accepts operator items only with an exact complete text block or complete line-run quote from a currently active human operator message at the cited seq; a quote proves the words, not their interpretation. Invalid JSON, inactive/wrong-source anchors, future seqs, or non-exact quotes discard the whole draft and use the deterministic template once, with no retry.
  - The newest active `enpoi-keeper` `user/message` is canonical prior derived state. Every wake and cache hit reads its `content` and strips the public wrapper; the raw `state/checkpoint` event and duplicated `source.sections` are not read for continuity. An API context repair to that line is visible immediately with zero model calls and zero appends on a cache hit; a deferred pending commit is dropped when the active keeper seq changed.
  - `checkpointMaxChars` bounds the complete emitted block (header + notice + body + telemetry), default 2400, validated 256–12000. Refresh triggers: clean segment cut, staleness floor, on demand; token pressure is only an extra trigger. A refresh finishing inside an open compaction/tool batch writes the durable event and parks its surface message until the boundary closes.
  - HMR/remount rehydrates compaction brackets from at most 64 events; an incomplete reverse probe holds surface commits conservatively until `turn/start` clears it. A cold reopen that finds the durable checkpoint but no active keeper surface node re-materializes the block at the same version.
  - The Watchtower State display reads the raw `state/checkpoint` event, so after an active-surface repair it may show pre-repair text until the next genuine refresh. That is display lag only, not a functional gap and not a reason to fake a version bump.
- Claim extraction: one pass per 8 non-aborted turn-ends or 5 minutes. Every keeper-extracted claim is tentative `untrusted_external`, including one whose exact human quote passed verification; operator trust stays with explicit root-session `memory_save`/`memory_confirm`/operator tools; a child session's `memory_save` is tentative too. Each batch carries `source: keeper`, a non-empty session id, a non-negative integer `batchBasedOnSeq`, and `settled: true` (see §5).

## 3. Compaction

- **Seat:** `personas.compaction` is the designated summariser seat (Settings → Agent Models, group BACKGROUND & SUPERVISION). Unassigned it INHERITS the session model — nothing changes by default. A `chain` resolves through the live `modelChains` service to its first usable member and the summariser request carries the group id, so the rest of the group fails over per request; a missing service, a stale/disabled chain, or one that resolves to zero members inherits with a warning instead of failing (`packages/compaction/compaction-basic/src/settings.ts:143-235`).
- **Economics:** a different summariser model loses the prompt-prefix cache and pays full input price for the whole region, so only free/local routes are reliably cheaper (`role-registry.ts:161-167`, `AgentModelsBody.tsx:217`). The readout follows the seat assignment, else the catalog default (`compaction-policy.ts:75-131`).
- **Settings** (`parameters.compaction`, read fresh per decision, fail-open per field — `settings.ts:97-126`; UI mirrors at `packages/client/ui-brand-enpoi/src/client/params-store.ts:77-90`):
  - `thresholdRatio` 0.6 — pressure fraction; `retainRatio` 0.16 — verbatim tail as a fraction of (window − output reserve)
  - `headroomTokens` 65 536 — output reservation/headroom; `retainTokens` 0 — absolute tail (wins over `retainRatio` when > 0)
  - `pruneThresholdChars` 8192, `pruneHeadChars` 4096, `pruneTailChars` 1024 — the pruner (§1)
  - Validation: ratios in (0,1], positive integers; an invalid field is ignored, never a failed turn; a retention ≥ the threshold falls back to the resolved config (`66…:564-571`). Per-model overrides exist only in the plugin Config `modelPolicies`, not in settings (`66…:581-583`).
- **Effective-policy readout:** Settings → Orchestration → Compaction shows the derived threshold and retained tail for the selected route, computed exactly like `resolveCompactSpec`: threshold = min(window × ratio, window − outputReserve − headroom), reserve = min(headroom, window/2); a `problem` line appears when the combination cannot fire or the catalog lacks the window (`compaction-policy.ts:63-131`).
- **Summariser call & window framing:** the LLM call is one cache-aligned pass; `summarizerInvocation()` caps the input by the summariser's own window — `inputBudgetTokens = window − min(maxTokens, window/2)` — keeps the system head + newest messages that fit, and marks `windowClipped` (`compaction-basic/src/index.ts:623-667`, `summarizer.ts:380-430`). On a clip, the checkpoint gains a code-assembled `[compaction coverage]` note naming the seq span and the recall tools (`region.ts:835-846`). No window metadata ⇒ raw replay as before. A single message larger than the whole budget is not split; it relies on the output-cap guard and then the mechanical fallback (`66…:585-601`).
- **Public-only summariser replay:** `projectSummarizationReplay` (`packages/compaction/compaction-basic/src/replay.ts`) passes clean surface messages through by reference, so a clean auxiliary request keeps its byte-identical cached prefix. Private reasoning is omitted from the summariser request but stays durable in the log; an assistant node with reasoning plus tool calls becomes labelled tool-call evidence, and a tool result whose call is outside the replay becomes labelled user-role evidence. A pass-through reasoning block or unsupported affected block refuses the model call: automatic compaction records the mechanical omission; manual `/compact` fails loudly. The checkpoint also carries a `[source span]` line with the exact shadowed seq range.
- **Authority index:** when a replayed role does not state its own authority, the summariser instruction gains a source index block of at most 32 entries and 4,096 characters. Only an authenticated human participant grants operator authority; generated checkpoints, runtime context, peer messages, public assistant output, and tool results are derived evidence. The instruction text prices at most 1,912 estimated tokens before the meter's block and tool framing even when clipping shrinks the rendered subset, and an explicit footer says unlisted messages have unknown authorship. It classifies source attribution, not truth, authentication, or intent.
- **Failure ladder** (`66…:115-124,321-343,603-618`): model summary → validation (coverage, shrink ratio, schema) → deterministic template/mechanical fallback. The model summary must shrink the route-priced span or it is rejected (`SummaryNotSmallerError`, `region.ts:470-482`).
- **Mechanical fallback (automatic transactions only):** replace the oldest balanced prefix of the selected span with ONE code-assembled omission stub, sized to beat the stub's price; the rest of the span stays verbatim; events stay in the log (`region.ts:489-530`). The stub text names recovery: "Recover anything you need … with `session_event_search` (keywords), `session_event_read` (seq), or `session_search`" (`summarizer.ts:84`). A durable `compaction/summary` event for a mechanical stub records `provider: ''` / `model: ''` — never price it as a model route (`66…:615-616,640-641`).
- **Smart vs mechanical — the automatic/manual seam:** automatic (`owner: 'current-turn'`, whole-surface) passes `allowMechanicalFallback: true`; manual `/compact` (`selected-span`) passes `false` and stays fail-loud so the operator sees the real error (`compaction-basic/src/index.ts:507,544-546`). The `compaction/summary-error` waterfall (`packages/compaction/compaction/src/index.ts:93-107`) gets a chance to repair the input before either path.
- **Never alters the transcript (hard rule):** compaction writes a surface `replace` only. The chat fold shadows a span only for a user-initiated revert; automatic compaction, manual `/compact`, and keeper checkpoints render every row, with no marker card (`66…:529-537`). Verify: `node ~/dsh-migration/evidence/ghost-revert/ghost-revert-probe.mjs <sessionId> --json` → `shadowRanges: []` and all rows rendered.

- **Leading prompt pinning:** `pinLeadingUserMessages` keeps the contiguous leading `user/message` run directly after the system head out of every compacted range and replays those nodes to the summariser as leading context, so the auxiliary request stays a byte-identical prefix up to the pinned run (`packages/compaction/compaction-basic/src/region.ts`, `summarizer.ts`). `pinScope: child` (default) applies it to subagent sessions only — a child's first prompt is its task brief — and `all` applies it everywhere; `0` restores the pre-pin boundary. The profile wires `1` for every preset.
- **Durable Facts inside the checkpoint:** the summariser instruction carries a `## Durable Facts` section (decisions with reasons, constraints, explicit operator requirements, exact paths/identifiers). It is ordinary checkpoint text — no format change — and `@deepseek-ai/dsh-compaction-basic/durable-facts` is the shared parser (`packages/compaction/compaction-basic/src/durable-facts.ts`). Design record: `.agents/notes/implemented/architecture/2026-10-23-compaction-durable-facts.md`.
- **Recall footer:** `recallFooter` is appended after `</compacted-summary>` and the mechanical stub names the recall tools only when every tool in `recallFooterTools` resolves in the compacting agent's scope; otherwise the text says only that the transcript is preserved. The footer is part of the framed checkpoint the shrink guard measures.
- **Compaction visibility:** no chat row (upstream rule). The context meter shows `Compacted N× · last X messages → checkpoint (~T condensed)` with a transient notice on each new compaction, session rows carry a `⟲N` badge, and the trajectory view lists each compaction request (`packages/llm/token-meter/src/compaction-projection.ts`, `ui-conversation/skeleton/ContextMeter.tsx`, `ui-trajectory`).
- **Compaction facts → memory:** after a successful `compaction/end`, `enpoi-memory` parses the section and saves each fact as a tentative claim with `origin: compaction`, `trust: untrusted_external`, and a source record (session, compaction, cwd, shadowed range). A committed checkpoint proves the summarization ran, not that model-extracted text is true; a root-session operator-authority write (`memory_confirm`, or a re-observed root-session `memory_save` of the same fact) is what commits it with the operator trust label. Seeded root forks are captured: `parentSession` alone does not make a child, so a fork header with `isSeeded: true` stays a root; a typed subagent origin or a positive delegation depth is skipped unless `compactionFactsIncludeChildSessions` is on (`enpoi-memory/src/compaction-facts.ts`, `session-authority.ts`). The intake pipeline rejects credential-shaped text for every origin, compaction facts are suppressed by token-set Jaccard near-duplicate matching (never fuzzy-merged), and retrieval scopes compaction facts to their own workspace (`pipeline.ts`, `retriever.ts`).

## 4. Whiteboard (authored truth, replace-in-place)

- Storage: `enpoi-orchestration.whiteboard` = `{ version, docs: { global?, projects: { <cwd> }, sessions: { <id> } } }`; entries have `kind` path|rule|fact|task, `pinned`, `version`, and stale flags (`profiles/web/packages/enpoi-whiteboard/src/board.ts:47-80,292-337`).
- Resolution on read: global → project → parent session (direct-child inheritance) → session, later scopes overriding by entry id (`board.ts:524-544`). Injected as `### Pinned context (vN)` after the keeper checkpoint (context order 143; `index.ts:1242-1256`).
- Budget: hard 1500 rendered tokens (4 chars/token estimate); an over-budget write is refused, never trimmed; session buckets GC at 200 newest (`board.ts:152-155,610-635,934`).
- Tools: `whiteboard_read`, `whiteboard_write`, `whiteboard_pin`/`whiteboard_unpin`, `whiteboard_forget`; `path` entries are validated on write and flagged `(stale)` — never auto-deleted (`board.ts:524-560`). A mutation returns a short receipt, not the board: changed ids (at most 8 listed plus a count), the checked view's stored tokens against the budget, the checked scope/facts, the caller's read tokens, the board version, and bounded stale/unverified ids; the whole receipt is capped at 600 code points, and `whiteboard_read` is the only full view (`index.ts:584-723,1146-1170`).
- Deterministic no-ops: repeating an identical id+content write, pinning an already-pinned entry, and unpinning an already-unpinned entry return `unchanged` (or an `already pinned`/`already unpinned` note) with no entry version, board version, or injected-context change; `whiteboard_forget` returns the removed entry with its text, so nothing is dropped silently (`index.ts:875,964-969,1001-1011,1042-1052,1097-1113`).
- Children read, never author: every mutation refuses a session with a durable parent (`CHILD_AUTHORING_REFUSAL`, `index.ts:456-460,916,993,1034,1086`), and the child catalog does not advertise the mutation tools at all (`SHARED_CHILD_DENY`). The shared child keep floor carries the read-only `whiteboard_read` and `compressor_retrieve`, which restores a crushed tool result from its `<<compressor:hash>>` locator and is not a board mutation. Council fibers keep the whiteboard even when all retrieval and mutation tools are denied (`enpoi-council/src/core/fiber.ts:117-126`).
- Failure modes: a hand-edited settings file can't break a turn (malformed entries dropped, `board.ts:290-337`); a pin inside a later-reverted span dies with the span; "forget" removes an entry but the injection is a projection, so nothing else changes.

## 5. Memory (durable, tool-driven — no passive block)

- Tools (`profiles/web/packages/enpoi-memory/src/tools.ts`): `memory_save` (≤400 chars; the same fact text and category are stored once; a credential-shaped fact is refused with `saved: false` and never stored; a near-match is still stored and the note names the closest active fact id and its Jaccard similarity; a root session writes with operator trust, a delegated child writes a tentative `worker`/`worker:<role>` claim that a root session must confirm), `memory_search` (returns facts with origin, saved date, state, and trust; whole facts in rank order within the character budget, with an omitted count; never injects), `memory_rescind` (root sessions only; tombstones a fact — never injected again; a delegated child gets `delegated_session_denied`), `memory_confirm` (root sessions only; commits a tentative claim with the operator trust label and a fresh commit time — a root `memory_save` already lands committed).
- Root-vs-child authority is one predicate, `isDelegatedSession`: a typed `origin: 'subagent'` header or a positive `delegationDepth` is delegated; a bare `parentSession` is delegated unless `isSeeded: true`, so a seeded root fork keeps root authority for `memory_confirm`, `memory_rescind`, and compaction-fact capture (`session-authority.ts`).
- Intake limits apply to every origin (compaction, keeper, `memory_save`): an empty fact or one over 400 characters is dropped, and a credential-shaped fact is skipped and never stored; the producer sees no exception (`pipeline.ts:29,72-80`, `secret-guard.ts`). `memory_save` names the secret reason to the model; a keeper claims pass or a compaction capture drops the fact and continues.
- Compaction and keeper writes arrive as tentative `untrusted_external` claims (see §3 and keeper README); even a keeper claim with a verified exact human quote is tentative because the quote proves wording, not interpretation. A model/tool call that invokes `memory_confirm` or `memory_save` still only asserts the operator label — it is not human fact verification. Retrieval scopes are unchanged: compaction facts stay scoped to their recorded workspace; keeper claims remain workspace-agnostic; the `memory_save` source record is audit-only.
- Boot/HMR reconciliation cancels leftover tentative claims from an unfinished run, but preserves one whose stored source record carries a producer-settlement proof: a compaction source with a non-empty compaction id, a keeper source with a non-empty session id, a non-negative integer batch seq, and `settled: true`, or a worker `memory_save` source with a non-empty session id and `settled: true` (its parent session and call id are attribution, not proof). This is a structural source-record check, not authentication.
- Recall of the transcript itself is a tool group: `recall` is always attached and exposes `session_event_search`, `session_event_read` and `session_search` (`profiles/web/packages/enpoi-tool-groups/src/catalog.ts`). Only diagnostics and trace tools remain on-demand behind `debug`.
- Retriever top-K and char budget come from `parameters.memory` (`retrieverTopK` 10, clamped 1–20; `retrieverCharBudget` 1200, clamped 200–4000), resolved fresh per call (`retriever.ts:29-30,44-56`; `tools.ts:259-270`). The budget applies after ranking: whole facts are included in rank order while their cumulative fact characters fit, the top-ranked fact is always returned even when it alone exceeds the budget, no fact is truncated, and the render states how many matches the budget omitted.
- Failure modes: an invalid or exact-duplicate fact answers `saved: false` with the reason; a secret-shaped save is refused and stored nowhere; a near-match save succeeds with a pointer to the closest id (nothing is merged); `memory_confirm` on an already-committed id says "Already <state>" rather than "unknown"; a search over the budget still returns the top fact and reports the omitted count; a fact containing a line break is quoted in search output so it cannot spoof a second result row.

## 6. Recall tools (the backstop)

- Mounted: `session_search`, `session_event_search`, `session_event_read`, `session_trace`, `session_event_trace` (`packages/session-query/tool-session-query/src/index.ts:66-109`). Search is FTS over directives/assistant text/tool metadata — never raw tool output (`66…:223-230`).
- Indexing runs off the hot path (background reconcile + targeted per-session indexing). A live session's documents are folded **incrementally**: only appended events are classified, and the SQLite writer applies row deltas (insert new documents, update surface flips by retained rowid) instead of deleting and rewriting the session; any failed write or non-continuation prefix falls back to the complete fold, with identical results (`packages/session-query/session-query-sqlite/src/live-documents.ts:36`; `src/index.ts:601-660`; measured ≈900× faster document build, ≈20,000× faster FTS row write at 20k docs — evidence `phase4/`). A cross-session search that must wait answers the coded `SESSION_QUERY_INDEXING` with `indexed/total` progress instead of aborting (`66…:732-744`).

## 7. Insights & `ds backfill`

- Context Insights (dsh-context) reads the persisted projection cache; the session log stays authoritative. Checkpoint writes are throttle-driven (`writeEveryEvents`, `writeIntervalMs` — both required) plus mandatory points: session creation, `turn/end`, disposal (`packages/session/session-projection-cache/README.md`).
- After a format/`stateVersion` change, stored rows become unreadable at the new generation: dashboards render blank until each session is opened once. Reindex with `ds backfill status` (first session-list page must show `withContextTimeline > 0`), then `ds backfill run` until it drains — idempotent, resumable (`--limit`), skips attached sessions (`~/.local/bin/dsh-projections-backfill.mjs`; playbook safeguard #15 in `~/dsh-migration/50-future-re-porting-and-upgrade-playbook.md:308`).
- Failure mode: `contextTimeline` missing from list rows makes the dashboard blank even when the cache is warm — check the exclusion list before re-running the fold.

## 8. Revert iterations (the ◀ x/y ▶ branch history)

Every user message committed over an earlier one belongs to a **variant group**: the original event is the anchor, each later send adds a variant whose `previousSeq` is the tree edge, and reverted-away versions stay restorable from their original events — no content or media is copied. The durable record is the fixed-size `revert/iteration` marker (log-only, `ignorable`, appended after the replacement with the assigned seq) (`packages/core/session/src/types.ts:480-492`). A pre-marker session derives the same edges from user-origin `surfaceOp.startSeq` replacements (`packages/api/session-controller/src/iteration-fold.ts:88-166`).

- **List:** `revertIterations` is cold-safe (an unattached session folds the log), bounded (default 50, max 200 groups/variants), returns capped text previews plus attachment ids, and marks a variant `surfaceActive` when it is a surface node or cited by a compaction checkpoint (`packages/api/session-controller/src/commands.ts:840-935`). The fold runs on host and client, so every attached client's x/y data refreshes from the event stream (`iteration-fold.ts:1-15`; wire block `SessionRevertFold.iterations`). History paging is incremental as well: prepending a page adopts the host's durable fold and folds only entries beyond its `asOfSeq`; a full-window replay remains only as the fallback for a window-derived fold (`packages/api/session-controller/src/client/sessions/session.ts:773-830`).
- **Restore is a branch swap, never a run:** `revertIterationRestore` validates the target before any write, then appends three `revert/state` markers (pin the current branch end, move the file boundary to the target branch end, disarm) plus one `revert/branch` whose `restoredSeqs` the surface fold splices in place of the current span; the target branch's original records are re-activated by identity — no user message, no turn, no model call (`commands.ts:930-1080`; `packages/core/session/src/surface.ts:453-530,658-662`; no-run proof `packages/api/session-controller/tests/revert-iterations.host.spec.ts`). Switching back and forth is exact because the displaced branch's records are recorded on each switch (`iteration-fold.ts:182-210`).
- **Attach on demand:** reverts, restores, branch switches, and file-conflict resolution resolve the session through the same attach path as a send, so they work on a freshly opened session whose agent is not live (`commands.ts:770-775,820-826,945-951,1122-1129`; `resolveAgent` `commands.ts:1197`).
- **Running turn:** a restore cancels the branch's running work, waits up to 5 s (`ITERATION_RESTORE_IDLE_TIMEOUT_MS`) for the agent to settle, and refuses with retryable `session/agent-busy` / `ITERATION_RESTORE_TURN_ACTIVE` **before any write** when it does not (`commands.ts:96-99,960-975`).
- **UI:** a visible user message in a group with more than one variant renders `◀ x / y ▶` (real buttons, localized `aria-label`s, `aria-live` position); arrows move a component-local preview only — transcript, log, and files are untouched until `Restore` writes through the host. Previews are fetched on first navigation, an active-pointer move resets the preview, and a failed restore shows "Restore failed — try again." on the row (`packages/client/ui-chat/src/client/chat/MessageItem.tsx:345-475`).
- **File state** follows the branch through the existing `revert/state` + file-revert plugin path: a backward switch reverts, a forward switch un-reverts; branches whose mutations were never captured surface through the conflict tray exactly like an ordinary revert.
- **Known limitation:** a specific variant can legitimately refuse with `revert-invalid` ("has no restorable branch records") when no commit independently shadowed its branch — a later user-origin commit from an independent earlier message can shadow a whole multi-group suffix, and pre-marker fallback logs record restorable branches only for spans a replacement cited, so some variants of a multi-group history are not restorable (`commands.ts:986-988`; `packages/api/session-controller/tests/revert-iterations.host.spec.ts:152-170`).

## 9. Failure modes → fix

| Symptom | Cause | Fix |
|---|---|---|
| Model sees a huge tool result | Pruner disabled/misconfigured; `head+marker+tail > threshold` ignored whole | Check `parameters.compaction.prune*`; confirm the plugin row is mounted; recover the middle with `session_event_read` |
| Brief stale or missing | both keeper routes dead → quarantine; or keeper disabled | Check `enpoi-keeper.log`; verify `personas.keeper` / Config routes; wait out the 5-min quarantine or fix the route |
| Keeper published a probe echo | shape gate rejected the landing (it is never published) | Route ladder is advancing; fix the keeper model or prompt env |
| Compaction never fires | retention ≥ threshold, headroom too large, or catalog has no window for the route | Read the Effective-policy readout `problem` line first |
| "Context was compacted but the chat lost messages" | Should be impossible by rule §3 | Run the ghost-revert probe; if rows are hidden outside a user revert, that is a regression |
| Whiteboard write refused | rendered board over 1500 tokens | Unpin/shorten entries; unpin is the only way to make one compactable |
| Cross-session search errors | FTS index not ready | Retry after the background pass; error names `SESSION_QUERY_INDEXING` with progress |
| Insights blank after update | stale projection cache generation | `ds backfill status`, then `ds backfill run` (check `withContextTimeline`) |

## 10. Token usage, prompt prefix anatomy & KV cache economics

- **Turn 1 input anatomy (~12.4k tokens)**:
  - 38 tools with detailed JSON schemas: ~8,200 tokens (32,924 characters of parameter definitions and descriptions).
  - System prompt (prefix + fleet doctrine + instructions): ~2,800 tokens (11,021 characters).
  - Initial turn context & user prompt: ~1,400 tokens.
- **KV prefix cache behavior**:
  - On Turn 1 Step 2, `cacheReadTokens` hits ~12,416 (a 99.9% cache hit). The model only bills/processes the delta tokens (e.g. 342 tokens).
  - Modern providers (DeepSeek, Claude, OpenAI) discount cached prompt tokens by 90–95% (e.g. DeepSeek bills prompt cache hits at $0.014 / 1M tokens).
  - The shared prefix parity law across `orchestrator`, `sysadmin`, and `creator` ensures that switching presets reuses the exact same 12.4k cached prefix without flushing the KV cache.

## 11. Session listing & query performance optimizations

- **`session.list` single-flight coalescing & window memo**:
  - Single-flight promise dedup (`listInFlight`) prevents redundant concurrent filesystem scans and is decoupled from caller abort signals (an aborting client never fails background readers).
  - In-memory 2,000ms ordered window memo (`cachedOrdered`) serves rapid repeat calls in ~50ms (down from 1,000ms+), with zero-staleness event listeners (`session/created`, `session/disposed`, `session/event`).
- **SQLite FTS5 PRAGMAs**:
  - `schema.ts` sets `synchronous = NORMAL`, `temp_store = MEMORY`, `mmap_size = 64MB`, `cache_size = -16MB` for the session-query FTS5 database, eliminating disk spills during window sorts.
- **ChatView virtual-window index memoization**:
  - Lazy getter `getIndexByKey()` memoizes the Map lookups across streaming chunks until item count changes, eliminating Map allocations on streaming chunks.

## 12. Operator context repair (one generated line)

`session-controller` exposes `contextRepairPreview` and `contextRepairApply` to the authenticated operator. A repair changes exactly one line inside one active surface `user/message` whose source is a `compact-checkpoint` or `enpoi-keeper` checkpoint; it never appends a generic event, exposes no model tool, and calls no model (`packages/api/session-controller/src/context-repair.ts`).

Crash repair is a separate path: a resumed log closes each unanswered `tool/call` from its durable approval audit — `TOOL_APPROVAL_NOT_DECIDED`, `TOOL_APPROVAL_DENIED`, and `TOOL_APPROVAL_EXPIRED` mean "not executed"; a granting decision stays `TOOL_OUTCOME_UNKNOWN` (01 §2; `packages/core/session/src/repair.ts`).

A compaction-checkpoint repair is a bounded amendment, not a general log mutation: it runs between turns, replaces exactly the one current checkpoint node, preserves that node's `compactionId` and `sourceCommandId`, cites it in `sourceEventSeqs`, and leaves the original events in the log. Preview planning replays the complete current log plus the proposed event through `validateCompactionEvents` before any append. It opens no compaction bracket and creates no fresh checkpoint; a new checkpoint still requires the full bracket. The amendment reuses the existing `user/message` and `compact-checkpoint` vocabulary, adds no event type, schema field, or format version, and needs an amendment-aware reader: older V4/V5 readers reject the amended log as a checkpoint replacement without a matching `compaction/start`.

- **Preview is read-only:** it requires the target seq, text-block index, SHA-256 of the complete block and the unique old line, and one non-empty replacement line. It validates a detached replay, captures the head seq and hash, and returns a one-use preview id, a plan fingerprint, before/after derived-context digests, and the minimal line diff. The token lives 5 minutes in process memory and at most 32 plans are retained.
- **Apply needs an idle lease:** the one-use token and fingerprint are consumed before any write. A live idle root Agent with no pending inbox, approval, or running descendant is required; the append runs under `Agent.runMaintenance`, revalidates head/target/surface before and after the pre-repair flush, and replaces the single surface position with `surfaceOp: { op: 'replace', startSeq: target, endSeq: target }`. The cited source-event chain is preserved.
- **Durable backup and receipts:** the default backup root is `$DSH_HOME/backups/context-repair`; it must be a private directory, not the harness home itself, and disjoint from the Session log tree. Before the append, the canonical artifact is copied with a 256 MiB default bound and no-follow descriptor, its decoded head is checked against the preview, and a `prepared` receipt stores the old/replacement text and artifact identity. `applied` means the append and post-append flush committed (a final receipt write failure returns `applied` with a warning); `partial` means the append committed but the durability barrier failed, and the response carries the prepared receipt path for rollback. The API makes no atomicity claim across those independent writes. `requestSnapshot` keeps reporting the last main request; the repair affects derived context only on a later request.
- **Current limitations:** the mounted persistence backend must expose a canonical artifact (`resolveCurrentLog`, currently the JSONL provider). Apply fencing and preview plans are process-local. `session/context-repair/committed` is optional process-local coordination, not a Session event, and the current keeper does not require it: repair continuity reads the authoritative active keeper surface on every wake and cache hit. A raw `state/checkpoint` display such as Watchtower State can lag until the next genuine refresh; that is display lag only, and no listener or version bump is required.

## 13. Subagent settlement reports (bounded)

A settled continuable child reports in one runtime-owned `user/message` in the parent (`source.kind: 'subagent-settled'`). The default is a bounded report view. `report_mode: "full-inline"` on a continuable dispatch raises the inline text threshold for that spawn only. See [settlement report bounds](../../packages/subagent/subagent/README.md#settlement-report-bounds) for configuration.

- A report inside the bounds keeps its original text and image blocks. An over-limit report keeps excerpts and the first images and names the child session; if the full text copy was saved, the notice also supplies the file locator, heading outline, and `read`/`grep` calls. Omitted images stay in the child session, not the text file. If no file copy was saved, use `session_event_search` and `session_event_read` on the child; a failed final flush means that log may be stale. The notice carries no reasoning or tool-call blocks.
- Token effect: one notice per settled Activation. The excerpts, heading outline, and retrieval text share the closing-report budget. Full inline and failed-flush fallback can use a larger budget. A child that also sends its own message costs the parent both.
- A settlement that lands after a user Stop-all is queued in the parent's next-turn inbox without waking a turn, and the operator's next turn claims it exactly once (`continuation-activation.ts:257-315,1125-1150`). A notice held for an absent parent lives only in the process-local outbox, so a restart can drop it; read the child's session instead (`list_agents` for the id, then `session_event_read`). The package README records this limit and the durable settlement marker it would need.

## 14. Goal rounds and automatic continuation

- An automatic goal round enters as a `user/message` with `source.kind: 'goal'` (`{ goalId, revision, round }`), so compaction and the summariser see ordinary user-role history, but it is not a human prompt: `pinLeadingUserMessages` pins only `source.kind: 'user'` messages without a peer participant, so a goal round never consumes a leading pin (`packages/compaction/compaction-basic/src/region.ts:443-451`; `packages/goal/goal-round-driver/src/index.ts:50-63,190`).
- A cancel without `keepInbox` (revert, session delete) withdraws a queued goal round from the inbox together with human prompts; settlement, job, relay, and context observations stay pending (`packages/core/agent-loop/src/inbox.ts:81-86,130-140`). The composer Stop and `peer.cancel` keep the inbox, so the round is withdrawn by the goal round driver at the next idle instead. The driver also removes a still-queued round at the next idle and, when the dropped attempt belongs to the current armed goal, pauses the goal, so later human input is not stranded behind a stale round (`goal-round-driver/src/index.ts:280-292`).
- With the subagent service mounted, the driver reserves no round while the root's continuable tree has a running descendant or an in-flight admission (`subagents.waitForTreeWork(root)`); a goal paused during that wait starts no round, and an idle member with parked input does not hold the root (`continuation-activation.ts:655-681`; `goal-round-driver/src/index.ts:166-177`). `maxGoalRounds` still caps rounds with the `round-limit` blocker, and `blocked` is refused until the configured number of rounds have started in the goal.
- Compaction may shadow earlier rounds like any user message; a round prompt is not re-pinned and no fresh agent or copied conversation prefix is created.
